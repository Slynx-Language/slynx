# Styles Implementation

Stylesheets on the language are intended to be syntax sugar over functions that returns an object that is a style. This will deprecate the ir definition of style tables, and lowering via specific ui instructions.
The idea then is to make something like the following slynx code, compile to an equivalent code

```slynx
object RainbowBackgroundArgs {
    t: percent,
    start: Oklch,
    end: Oklch,
}
stylesheet RainbowBackground(args: RainbowBackgroundArgs) uses Rounded(32px){
    let lerped = args.start.lerp(args.end, args.t);
    styles {
        foregroundColor: args.start.asRgba(),
        backgroundColor: lerped.asRgba() animating(300ms, linear),
        hover(300ms, ease-in-out) {
            foregroundColor: args.end.asRgba()
        }
    }
}
```

```slynx

object RainbowBackgroundArgs {
    t: f32,
    start: Oklch,
    end: Oklch
}
object Rounded {
    border_radius: f32
}
struct RainbowBackground: Style {
    border_radius: f32,
    background_color: Rgba,
    foreground_color: Rgba,
    func new(args: RainbowBackgroundArgs): Self {
        let lerped = args.start.lerp(args.end, args.t);
        let rounder = Rounded::new(32.0);
        Self(
            border_radius: rounder.border_radius,
            background_color: lerped,
            foreground_color: args.start,
        )
    }
    
    func apply(&self, target: impl StyleTarget) {
        target.set_border_radius(self.border_radius);
        target.set_background_color(self.background_color);
        target.set_color(self.foreground_color);
    }
}
```
where an scheduler is responsible for running the animations, in case, of every possible property type.

```slynx
object MyScheduler: Scheduler {
  rgba: Pool<Animation<Rgba>>,
  point: Pool<Animation<Vec2>>,
  ... functions to insert
  func tick(&mut self, dt: f32):void {
    for rgba in self.rgba {
      rgba.tick(dt);
    }
    ... same logic for other pools
  }
  func getRgba(&self, id: Id<Animation<Rgba>>): Rgba {
    self.rgba.get(id).current_value
  }
  ... same logic
}
```
Then what the component does when the style changes is to request an animation to it. For example:
```slynx
component MyComponent {
    pub color: Rgba;
    Div {
        style: RainbowBackground(RainbowBackgroundArgs(start:color.toOklch(), t: 0, end: Black.toOklch())),
    }
}
```

Yes this is very specific, but I cannot explain it without an code example to explain how this should work. The idea is to make it request for the global animation scheduler to insert a new animation with the duration, and lerping values.
To avoid pointers, and etc, a pool for each lerpeable value used in animations should be generated. this should be generated by the compiler when checking what styles some stylesheet support. 
If at the given time the stylesheets support properties with types: Rgba, Pixel, Vec2, etc, then an scheduler should be able to handle these 3 types, the idea then is for the compiler to automatically generate an interface requiring the
3 types to be handled.
The idea for the language then is that, on animating something, while the animation is still alive,the component that is being animated should keep marking itself as dirty everytime, so the application loop is able to look at it and
update it while the animation lives. When it dies, then, it doesn't mark itself as dirty anymore, and thus stop re-rendering. The animation ID should be at the component since it's the one that is being affected, so it should also 
be able to know when it finished, the current state of it, etc. 
Since this lowering is specialized for the HIR, the IR keeps itself dumb, and then, able to compile to any other target.
